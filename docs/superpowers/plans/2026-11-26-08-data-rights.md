# Part 8: Data rights and retention, plan

Design: `docs/superpowers/specs/2026-11-26-08-data-rights-design.md` (approved 2026-11-26).
Branch: `feat/data-rights`. Server first, then the app. Every task ends with its tests green and a commit in the repo's style.

## Differences from the design, found while reading the code

- **Retention settings** get their own Owner-only routes, `GET` and `PATCH /admin/retention`, with their own columns on `platform_settings`. The big `Settings` struct and the dashboard settings page are not touched; a dashboard form is left for later.
- **The current session stays open during the cooling-off**, but gated: every other route answers 403 `deletion_pending`. Other sessions are revoked at the request. The app needs that one session to show the "Keep my account" screen.
- **The inventory gains** `stores` and `store_branches` business phone and pickup address, `payout_accounts` and `payouts` account fields, `shipments.courier_phone_enc` and `identity_checks.full_name_enc`. The design's guard test exists to catch exactly this kind of omission.
- **Store owners** can already close a store (`DELETE /stores/{key}`), so `owns_store` means a store of theirs with `deleted_at IS NULL`.

## Tasks

1. **Migration 0050.** `deletion_requests` (user, status `pending | cancelled | done`, requested_at, due_at, deferred_count; one pending per user), `data_exports` (user, status `pending | ready | failed`, body_enc, requested_at, ready_at, expires_at; one live per user), retention columns on `platform_settings` with bounds, `users.erased_at`, and notice kinds `deletion_scheduled`, `deletion_due_soon` if needed.
2. **Blockers** (`privacy::blockers`): `open_order` (buyer orders not in completed, cancelled, refunded; seller-side orders of stores they own or are members of, same), `open_dispute` (status not decided or withdrawn, either side), `owns_store`, `money_in_flight` (payouts in scheduled, sending, pending, unknown; refunds in requested, processing). One function returns the list of codes.
3. **Request, status, cancel** (`POST/GET/DELETE /me/deletion`): password check, blockers, revoke other sessions, audit with ids only. **Pending gate** in the `AuthUser` extractor: 403 `deletion_pending` except for `/me/deletion`, `/me/export*` and logout.
4. **Erasure** (`privacy::erase`): one transaction per user, in the inventory's order; `users` becomes an empty shell (display name "Deleted user", `phone_enc` emptied, `phone_idx` rotated to random bytes, password cleared, `deleted_at` and `erased_at` set); re-checks blockers and defers if one appeared. A **job** `erase_accounts` runs it for due requests. The **guard test** compares the schema with the inventory.
5. **Export** (`POST/GET /me/export`, `GET /me/export/file`): password, one per 24 hours, a job builds the JSON, stored encrypted, deleted after 7 days; download only by its owner with `Cache-Control: no-store`.
6. **Retention jobs** `retention`: chat messages, flags, suggestions and strikes on the chat window (longer while a dispute on the order is open); delivery addresses after their window; notices; stale push devices; attempt rows; expired exports; money and order records past the records window. Owner routes for the windows.
7. **Server tests and docs**: each blocker, the gate, restore, the purge of every inventory table for a person with data in all of them, the guard test, export contents and access, retention boundaries.
8. **App**: `features/privacy/` (models, repository, controller, pages), the Privacy and data page under Account, the `deletion_pending` screen and the router gate, tests.
9. **Wire check** against a real local server, README and roadmap, full checks, push, then ask before opening a PR.

## Order and checks

Tasks 1 to 7 are the server and can be tested without the app. Run the whole server suite from `server/` with Postgres 17 on 5433 and `DATABASE_URL` set; `cargo fmt --check`, `cargo clippy --all-targets -D warnings`. For the app: `build_runner`, `dart format`, `flutter analyze`, `flutter test`. A purge job must never skip a test because a service is down.

## Not in this part

A dashboard queue, privacy notice text, a retention form in the dashboard, photo files in the export, SMS about a due deletion.

## Status

Built on `feat/data-rights`. Server: migration 0050, the `privacy` module, three jobs (`erase_accounts`, `build_exports`, `retention`) and nine tests in `server/tests/privacy.rs`, including the guard test. App: `features/privacy/`, the `SessionDeleting` state, the router gate and tests. A real-server wire check passed.

Also different from the plan as written: addresses are emptied rather than deleted (an order's delivery option points at one), the records window deletes dispute statements only (money and order records are not deleted yet, see the roadmap), and no inbox notice is created about a due deletion.
