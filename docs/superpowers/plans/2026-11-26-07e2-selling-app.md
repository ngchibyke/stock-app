# Part 7e-2: Selling Screens in the App Implementation Plan

**Goal:** the owner-approved design (`docs/superpowers/specs/2026-11-26-07e2-selling-app-design.md`, approved 2026-11-26): a separate Sell area with identity, store, payout, products with guided photos, orders, branches, team, reviews and disputes, and walk into my store.

**Architecture:** `app/lib/features/sell/`. Hand-parsed models (`core/json_read.dart` readers, as the address feature), three repositories behind interfaces with Dio implementations and in-memory fakes for widget tests: `SellRepository` (seller entry, identity, stores, payout, branches, team, invites), `ListingRepository` (products, uploads), `OrdersRepository` (orders, reviews, disputes). Riverpod providers; the chosen store is one provider checked against `GET /stores/mine`. The app's copy for this area is in `sell_strings.dart`; the identity notice is in its own file for legal review. The server is unchanged.

## Global constraints

- Personal data stays in memory: the NIN, phone numbers, payout account numbers and addresses are never logged, persisted or put in a route; model `toString` never prints them.
- Spacing from `Tokens`, colours from `context.tokens`, every tappable thing is a Material button or `Pressable`.
- Money is integer kobo (`core/format/money.dart`).
- Checks from `app/`: `dart run build_runner build`, `dart format --output=none --set-exit-if-changed .`, `flutter analyze`, `flutter test`. Never claimed run on a device.
- Commits are conventional and carry no AI attribution.

## Tasks

1. Foundations: `ApiClient.patch`, models, `SellRepository` (API and fake), providers, strings, routes `/sell/...`, Account entry.
2. Become a seller (access code) and the identity check: notice, NIN input (digits only, 11), `SelfieCapture` interface with a development fake, waiting and result states.
3. Create a store (district choice) and the payout account.
4. The Sell shell (bottom bar, store switcher) and the Store tab (details, delivery, collect notice, walk into my store).
5. Photos: pure crop/resize maths, guide sheet, camera overlay page, gallery, uploader; Products tab and product form.
6. Orders tab and order detail with steps, handover code entry.
7. Branches and Team (with the invites inbox in Account).
8. Reviews with replies, disputes with answers.
9. Wire checks against a real local server, README notes, roadmap and plan status, full checks.
